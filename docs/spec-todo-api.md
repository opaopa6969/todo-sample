# Todo API 仕様

この文書は、`/todos` API の外から見える契約と、変更時に維持する制約を記録する。実装の転記ではなく、実装だけでは判断できない前提を残す。

## 目的と境界

- このサンプルの目的は、認証を `volta-auth-proxy` に置き、アプリでは受け取った識別子でデータを分離する構成を学べるようにすること。
- 認証・セッション・永続化はこのアプリの責務にしない。ストレージはプロセス内だけで、再起動時に消える。
- proxy を通さないローカル確認のため、識別ヘッダが空または未設定の場合は共有バケットにフォールバックする。この挙動を本番の認証境界として扱わない。

## HTTP 契約

ベース URL は開発時 `http://localhost:27743/`。エンドポイントは次のとおり。

| Method | Path | 成功時 |
|---|---|---|
| GET | `/todos` | `200` と配列 |
| POST | `/todos` | `201` と作成した todo |
| PUT | `/todos/{id}` | `200` と更新した todo |
| DELETE | `/todos/{id}` | `204`、本文なし |

POST の body は `title` が空でない文字列である JSON オブジェクト。PUT は `title` と `done` の部分更新を受け付ける。存在しない todo は `404`、対象外のメソッドやパス形は `405` または `400`、不正な JSON は `400` とする。request body は最大 64 KiB で、超過時は `413`。

レスポンスの todo は `id`、`title`、`done`、`createdAt` を持つ。`id` はプロセス内で採番し、`createdAt` は作成時刻を表す。日時の単位・表示形式を変更してよいかは TODO: 要確認。

## 分離と不変条件

`X-Volta-Tenant-Id` と `X-Volta-User-Id` の組をデータバケットのキーとする。同じ組だけが互いの todo を読み書きでき、片方でも異なる組からは見えない。空または未設定の値はそれぞれ `public`、`anonymous` とする。

このヘッダを誰が付与し、アプリへ直接到達できないようにする方法はデプロイ環境の責務である。アプリ単体でヘッダ偽装を防げるか、また本番でフォールバックを禁止する設定を設けるかは TODO: 要確認。

## 変更時に壊してはいけないもの

- パス、HTTP メソッド、ヘッダ名、フォールバック値、ステータスコード。
- tenant × user をまたいだデータ参照・更新が起きないこと。
- インメモリ・依存最小という教材上の前提。
